# Offline-конверсия назначений профилей

Этот отдельный Python 3.11+ инструмент не подключается к DME и не запускается при входе игрока. Перед развёртыванием runtime с единственной `pref_job_slots` нужно конвертировать существующие сохранения при остановленном сервере. Агент не запускает инструмент против production без отдельного разрешения.

Формат подтверждён по `code/modules/client/preferences_savefile.dm::load_path/load_preferences/save_preferences` и `code/datums/json_savefile.dm`: `data/player_saves/<первая буква ckey>/<ckey>/preferences.json` содержит корневые настройки игрока (`version`, `default_slot`), корневые карты назначений и отдельные вложенные `characterN`. Конверсия обрабатывает только `*/*/preferences.json` внутри явно выбранного корня, проверяет путь и корневую структуру. Поддерживаемые версии сохранения: 32–52, как в этой ревизии игры. Более новые/устаревшие версии, обёртки, повреждённые character-секции, повторные JSON-ключи и неправильные карты отвергаются.

Положительные `job_assigned_profiles` переносятся в `pref_job_slots`. Любое явное новое значение, включая `0` и `-1`, побеждает старое. Затем старый корневой ключ удаляется. `[]` и `null` означают пустую DM-карту. Верхняя граница слота здесь не ограничивается: потеря доступа к сохранённому слоту не должна уничтожать назначение. Остальные поля и содержимое character-секций сохраняются; преобразование идемпотентно.

1. Остановите сервер и другие процессы записи сохранений. Сохраните полную независимую резервную копию `player_saves`.
2. Запустите просмотр изменений (это режим по умолчанию; файлы, backup и временные файлы не создаются):

   ```powershell
   py -3 -B tools/migrate_job_slots/migrate.py D:\Server\data\player_saves
   ```

3. Разберите все `ERROR`. Файл с неожиданной структурой или повреждёнными значениями остаётся нетронутым, без reset. Отчёт показывает относительные пути и причины, без значений настроек. Не развёртывайте новую runtime-версию, пока не обработаны все отказавшие файлы.
4. Укажите новый каталог backup вне `player_saves` и подтвердите остановку всех писателей:

   ```powershell
   py -3 -B tools/migrate_job_slots/migrate.py D:\Server\data\player_saves --apply --server-stopped --backup-dir D:\Backups\job-slots-before-deploy
   ```

Для каждого изменяемого файла сначала создаётся точная копия исходных байтов по тому же относительному пути в backup. Существующий backup не перезаписывается. Затем данные записываются во временный файл рядом с исходным и заменяются атомарным `os.replace`; перед заменой проверяется, что исходные байты не изменились. Ошибка записи оставляет исходный файл и backup для восстановления; временный файл удаляется. Флаг остановки — подтверждение оператора, он не завершает процессы сам. Не изменяйте сохранения параллельно конверсии.

Инструмент продолжает отчёт по остальным файлам при ошибке. Код выхода `0` означает успешную проверку/конверсию всех найденных файлов; `1` — как минимум один отказ; `2` — ошибка запуска или пустой/неправильный корень. При повторном apply уже конвертированные файлы и backups остаются нетронутыми. Для повторного восстановления из частичного сбоя используйте отдельный новый backup-каталог после проверки причин.

Проверки выполняются только на автоматически удаляемых TEMP-fixtures, без обращения к реальным сохранениям:

```powershell
py -3 -B -m unittest discover -s tools/migrate_job_slots/tests -v
```

После конверсии повторный dry-run должен показать `changed=0 errors=0`. Храните backup отдельно от игрового кода; возврат данных выполняйте при остановленном сервере из полной резервной копии, если понадобится откат развёртывания.
