# Расширение существующего кода
Эта памятка дополняет [AGENTS.md](../AGENTS.md); правила разработки, ревью и проверки результата находятся там и в указанных им guides.

## Выбор места изменения

Выбирай место по соседнему коду, владельцу состояния и цене будущих upstream merge. `modular_bandastation/` содержит как новые типы, так и overrides, но не является обязательным местом для каждой новой строки логики. Небольшое исправление общего алгоритма может остаться в существующем файле.

Перед генератором установи все входы и перезаписываемые выходы.

До выбора точки расширения проследи entrypoint → include → вызовы → состояние → потребитель. Сначала проверь существующие реализации и точки расширения:

| Потребность | Возможный подход |
| --- | --- |
| Достаточно настроить объект | Поля subtype либо изменение собственного состояния после инициализации |
| Есть подходящий сигнал или hook | Проверить момент вызова и контракт обработчика, затем использовать его |
| Условие до штатного действия | Override с проверкой перед родителем, если контракт это допускает |
| Дополнительные возвращаемые данные | `. = ..()`, затем изменение результата с учётом владения списком |
| Нужны локальные данные внутри процедуры | Небольшая локальная правка либо узкая точка расширения без копирования алгоритма |

Это варианты, а не обязательная последовательность. Сигнал, override или дополнительный helper не нужны, если небольшая правка существующей реализации решает задачу проще.

Если выбран модпак, [example/_example.dme](../modular_bandastation/example/_example.dme) и [example/_example.dm](../modular_bandastation/example/_example.dm) показывают includes и lifecycle. Новый `.dm` должен входить в действующий include graph; наличие файла в каталоге само по себе этого не обеспечивает.

## Контракт родителя и результата

`. = ..()` сохраняет результат родителя и позволяет дополнить его; `return ..()` сразу завершает процедуру. Тип, смысл результата и необходимость родителя устанавливай по исходникам. Например, `JOB_AVAILABLE` равен `0`, поэтому `if(!.)` не означает ошибку допуска.

Вызов `..()` может создать тело, выдать вещи или сохранить данные. Изменение `.` не отменяет этих действий: запрещающую проверку ставят до эффекта; rollback выполняют до удаления необходимых объектов. Фиктивный вызов родителя не сохраняет контракт.

Список результата может быть общим. Если вызывающий код должен менять только собственные данные, используй копию согласно контракту; `Copy()` не копирует вложенные списки. Не подменяй глобальные job datums или активные preferences на время вызова, который может ожидать.

## Правка upstream

Отмечай изменения upstream по соглашению `BANDASTATION EDIT|ADDITION|REMOVAL` из AGENTS.md. Для блока достаточно START/END; повторные inline-метки внутри него не нужны. Собственные модульные файлы такими метками не обрамляют.

Если нужна внутренняя точка расширения, оставляй её узкой и сохраняй проверки и побочные эффекты исходного пути. Размещение реализации и состояния выбирай по тем же критериям владения и сопровождаемости. Не копируй весь штатный алгоритм ради одного дополнения и не сохраняй неисполняемый оригинал за безусловным ранним `return` ради маленького diff.

Для TGUI сначала проверь DM `ui_data/ui_act`, реальный компонент и существующие точки композиции. Небольшое дополнение интерфейса не требует замены всего dispatcher или render.

## Проверка

Выбирай проверки по разделу Testing and verification в [AGENTS.md](../AGENTS.md). Build targets сверяй с `tools/build/build.ts` и [build README](../tools/build/README.md). Include-инспектор показывает текстовые ссылки; браузерный кадр подтверждает веб-сценарий. Ни один из них не заменяет compile или BYOND runtime.

Смотри весь diff к базе задачи, а не только последний коммит: штатные алгоритмы действительно вызываются, нет копий, неисполняемых хвостов и лишних обёрток. Compile PASS этого не доказывает. Выполни `git diff --check`.

[Task state](TASK_STATE.md) и [MCP](TOOLS.md) — дополнительные средства. Для изменения без них достаточно подходящих доступных инструментов и фактического отчёта по правилам AGENTS.md.
