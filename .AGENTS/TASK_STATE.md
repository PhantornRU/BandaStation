# Локальные записи задач
Task state — опциональное средство для длительной задачи, передачи работы или восстановления контекста. Наличие нескольких этапов само по себе не требует четырёх документов; используй их, когда они облегчают продолжение. Записи хранят контекст, не запускают работу и не выдают разрешений.

Рабочие записи находятся в локальном `task_state/<task-id>/`, шаблоны — в `.AGENTS/templates/`.

```powershell
tools/agents/task.ps1 -Action list
tools/agents/new-task.ps1 -TaskId 20261024-example -Title 'Проверяемый результат'
tools/agents/task.ps1 -Action resume -TaskId 20261024-example
```

| Файл | Содержание |
| --- | --- |
| PLAN.md | Цель, владелец, пути записи, исходный HEAD/dirty state и критерии готовности |
| TODO.md | Статус, сделанное, следующий шаг, последняя проверка и блокер |
| DECISIONS.md | Решения, причины, источник указания и проверяемые допущения |
| EVIDENCE.md | Команда или сценарий, проверенные входы, результат и его предел |

Статус в TODO: `active`, `blocked`, `done`, `superseded`. `done` означает выполненную приёмку; блокер содержит условие продолжения, замена — ссылку на новую задачу. Эти статусы относятся только к локальным заметкам.

При продолжении существующей задачи укажи TaskId явно, прочитай TODO и сверь HEAD, dirty state и затронутые файлы. Остальные документы читай по необходимости. `resume` только читает; он не меняет статус и не выбирает задачу автоматически.

Для совместной работы у каждого изменяемого файла должен быть один согласованный писатель. Оркестратор задаёт каждому цель, входы, владельца, точные пути записи, ограничения и критерии результата. Пересекающийся файл ведёт один интегратор; перед записью перечитывает текущую версию. Общие генераторы, сборки и изменяющие runtime проверки выполняются последовательно. После интеграции проверяй конечное дерево.

Task state не реализует leases, блокировки или очереди; правила запуска агентов, выбора модели и reasoning определяются пользователем и средой, а не этим набором.

Старый `.AGENTS/local/` не используется для новых записей: на Windows он пересекается с обнаружением skills. Явный `task.ps1 -Action migrate -TaskId <id>` копирует существующую задачу без перезаписи, сохраняя исходник. При передаче набора чужая история задач не экспортируется. Секреты и тяжёлые логи в task state не хранятся.
