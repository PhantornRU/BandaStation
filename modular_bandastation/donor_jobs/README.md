# Донатные профессии

Модуль добавляет 22 профессии для подписчиков, расширяет существующий Prisoner и предоставляет бесплатный вариант «Доставщик» Cargo Technician. Ролевые идеи взяты из Paradise SS220 #824/#1027; экипировка и игровые механики используют существующие типы BandaStation. Варианты сохраняют место, ограничения и job-ban своей канонической профессии.

| Тир | Профессии |
| --- | --- |
| T1 | Заключённый |
| T2 | Парикмахер, Банщик, Крупье, Официант, Послушник, Борец, Музыкант, Актёр |
| T3 | Сервис-администратор, Турист ТСФ, Турист СССП, Менеджер по клинингу, Охранник сервиса, Мигрант, Безработный |
| T4 | Адъютант, Представитель ТСФ, Представитель СССП, Торговец |
| T5 | VIP-гость корпорации, Банкир, Клоун СБ |

Уровни накопительные. Художник использует штатные холст, палитру и краски, подмастерье — пояс инструментов; дворецкий и горничная получают собственные сочетания одежды и принадлежностей. Старые ключи названий продолжают разрешаться. Торговец начинает с небольшим фиксированным набором: две четырёхцветные ручки, фонарь, мелки, очки и зажигалка. VIP получает 2000 кредитов, банкир — 5000; предусмотренные импланты выдаются штатным outfit.

Комплект выбирается на сервере до личного loadout; видовая подготовка сохраняется. Предметы используют слоты и storage API; переполнение сумки у новых комплектов остаётся рядом с персонажем с сообщением. Preview не выдаёт содержимое контейнеров, деньги и импланты; повторный callback и reconnect не повторяют выдачу.

Для локального запуска:

1. Соберите репозиторий через `tools/build/build.bat build` с версией BYOND из `dependencies.sh`.
2. В локальной копии `config/game_options.txt` включите `DONOR_JOBS_ENABLED` для новых профессий и отдельно `DONOR_PRISONER_GATE` для донатных вариантов Prisoner и вакансий 5/3. Перезапустите сервер. Явные настройки вакансий карты и `jobconfig.toml` имеют штатный приоритет.
3. Откройте `tgstation.dmb` через DreamDaemon. На localhost штатные `ENABLE_LOCALHOST_RANK` и `LOCALHOST_DONATE_TIER` задают уровень для проверки.
4. В настройках профессий выберите профиль персонажа и вариант. Указанный в строке профиль определяет ограничения и вариант при появлении.

Назначения профилей хранятся только в `pref_job_slots`: отсутствие записи или `0` означает текущий слот, `-1` — случайные имя и внешность текущего персонажа, положительное число — сохранённый слот. UI изменяет их через `set_job_slot` с проверкой владельца и `edit_slot`; приоритеты `job_preferences` не содержат назначений профилей. Формат загрузки не удаляет настройки временно недоступных профессий или слотов. Перед развёртыванием конвертируйте старые сохранения при остановленном сервере отдельным [offline-инструментом](../../tools/migrate_job_slots/README.md): сначала dry-run, затем запись с обязательным backup. Runtime не читает старую карту и не поддерживает старое действие.

При выключенном `DONOR_JOBS_ENABLED` новые профессии отсутствуют в списке назначений. При выключенном `DONOR_PRISONER_GATE` Prisoner использует обычные ограничения, вакансии 0/4 и штатную экипировку; сохранённые варианты доступны после повторного включения. «Доставщик» доступен независимо от обоих флагов.

Шаблоны новых должностей доступны через штатную авторизацию CentCom ID-программы. Подписка проверяется при выборе профессии и окончательном назначении; полученные предметы и доступы используют обычные игровые правила.

DM-проверки подключены единожды к штатному набору unit tests. Запуск: `tools/build/build.bat dm-test -Werror -ITG0001 -Iloop_checks`. Donor-модуль проверяет тиры/варианты, реальные outfits, деньги при чужой стопке и полной сумке, preview, повторные callbacks, ID и публичную должность Prisoner. Профильные set/current/random/reset/save/reload, повреждённые данные и чужие/устаревшие действия проверяются в `job_slots_preferences/code/tests/`; admission, последний слот, handover, Assistant fallback и независимая запись Prisoner — в `jobs/code/tests/`; отмена подготовленного Dynamic — в `dynamic/code/tests/`. Общая очистка mock-игроков принадлежит тестам `jobs` и не включается в production DME. Полноценная ручная проверка требует BYOND-клиента: обычный Cargo Technician/Доставщик, донатная роль и поздний Prisoner с осмотром экипировки и ID.
