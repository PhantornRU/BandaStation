# Донатные профессии

Модуль добавляет 22 профессии для подписчиков, расширяет существующий Prisoner и предоставляет бесплатный вариант «Доставщик» Cargo Technician. Ролевые идеи взяты из Paradise SS220 #824/#1027; экипировка использует существующие типы BandaStation, кроме уникальной формы/HONK-ружей клоуна СБ и отсутствовавших изображений одежды ТСФ/СССП. Варианты сохраняют место, ограничения и job-ban своей канонической профессии.

| Тир | Профессии |
| --- | --- |
| T1 | Заключённый |
| T2 | Парикмахер, Банщик, Крупье, Официант, Послушник, Борец, Музыкант, Актёр |
| T3 | Сервис-администратор, Турист ТСФ, Турист СССП, Менеджер по клинингу, Охранник сервиса, Мигрант, Безработный |
| T4 | Адъютант, Представитель ТСФ, Представитель СССП, Торговец |
| T5 | VIP-гость корпорации, Банкир, Клоун СБ |

Уровни накопительные. Художник использует штатные холст, палитру и краски, подмастерье — пояс инструментов; дворецкий и горничная получают собственные сочетания одежды и принадлежностей. Старые ключи названий продолжают разрешаться. Торговец начинает с небольшим фиксированным набором: две четырёхцветные ручки, фонарь, мелки, очки и зажигалка. VIP получает 2000 кредитов, банкир — 5000; предусмотренные импланты выдаются штатным outfit.

Комплект выбирается на сервере до личного loadout; видовая подготовка сохраняется. Предметы используют слоты и storage API; переполнение сумки у новых комплектов остаётся рядом с персонажем с сообщением. Preview не выдаёт содержимое контейнеров, деньги и импланты; повторный callback и reconnect не повторяют выдачу.

Для локального запуска:

1. Соберите репозиторий через `tools/build/build.bat build` с версией BYOND из `dependencies.sh`.
2. В локальную копию `config/game_options.txt` добавьте строку `DONOR_JOBS_ENABLED` для новых профессий и отдельно строку `DONOR_PRISONER_GATE` для донатных вариантов Prisoner и вакансий 5/3. Перезапустите сервер. Явные настройки вакансий карты и `jobconfig.toml` имеют штатный приоритет. Пустые секции новых профессий уже есть в рабочем конфиге; параметры для них приведены в [jobconfig.example.toml](jobconfig.example.toml). Копируйте нужные ключи внутрь существующих секций, избегая повторного объявления таблиц.
3. Откройте `tgstation.dmb` через DreamDaemon. На localhost штатные `ENABLE_LOCALHOST_RANK` и `LOCALHOST_DONATE_TIER` задают уровень для проверки.
4. В настройках профессий откройте вкладку «Подписка» справа от заголовка «Что делать если не удалось войти?». Профессии разделены по тирам в возрастающем порядке; недоступный тир помечен замком. При недостаточной подписке интерфейс блокирует выбор приоритета и варианта по существующему серверному `lock_reason`; сброс ранее выбранного приоритета остаётся доступен. Штатные серверные проверки назначения сохраняются. Вариант, приоритет и профиль находятся в одной строке. Указанный профиль определяет ограничения и вариант при появлении. Бесплатный «Доставщик» остаётся во вкладке «Обычные».

Группировка и выбор варианта принадлежат TGUI-модулю `tgui/packages/tgui/bandastation/donor_jobs/`, стили — `styles/bandastation/donor_jobs.scss` со статическим импортом из модульного `JobHudIcon`. Native JobsPage подключает компоненты и фильтр; модульные `JobsLayout`/`JobsSection` сохраняют исходные колонки и единственный native renderer строки. Вкладки используют существующее место кнопок заголовка Section и не смещают нижний ряд действий. Отбор использует серверный `required_tier`; при отсутствии платных профессий переключатель скрыт. Модульный priority hook захватывает слот отрисованной строки, чтобы сервер мог отклонить ответ устаревшего UI.

Назначения профилей хранятся только в `pref_job_slots`: отсутствие записи или `0` означает текущий слот, `-1` — случайные имя и внешность текущего персонажа, положительное число — сохранённый слот. UI изменяет их через `set_job_slot` с проверкой владельца и `edit_slot`; приоритеты `job_preferences` не содержат назначений профилей. Формат загрузки не удаляет настройки временно недоступных профессий или слотов. Перед развёртыванием конвертируйте старые сохранения при остановленном сервере отдельным [offline-инструментом](../../tools/migrate_job_slots/README.md): сначала dry-run, затем запись с обязательным backup. Runtime не читает старую карту и не поддерживает старое действие.

Для сопровождения код разделён по владельцу состояния:

- `job_slots_preferences/code/character_selection.dm` читает выбранный профиль; lobby владеет зафиксированным `assigned_character` до передачи тела.
- `job_slots_preferences/code/latejoin_context.dm` захватывает и сравнивает настройки входа. Меню проверяет всю карту назначений после SQL и модального ответа; окончательная попытка — только выбранную профессию. Смена профиля, назначений или toggle отменяет устаревший ответ меню.
- `jobs/code/player/latejoin.dm` выполняет допуск и handover; native continuation отвечает за оснащение и последующий учёт. Проверки до и после ожиданий относятся к разным моментам и намеренно сохранены.
- `donor_jobs/code/spawn_context.dm` хранит выбранный комплект на созданном теле. Экипировка, ID/PDA, запись и приветствие используют этот выбор; повторно читать изменившиеся настройки для него не нужно.
- TGUI `JobsLayout.tsx` содержит layout и выбор обычного списка либо тиров; в обоих случаях строку рисует один native `JobRow`.

При выключенном `DONOR_JOBS_ENABLED` новые профессии отсутствуют в списке назначений. При выключенном `DONOR_PRISONER_GATE` Prisoner использует обычные ограничения, вакансии 0/4 и штатную экипировку; сохранённые варианты доступны после повторного включения. «Доставщик» доступен независимо от обоих флагов.

Преступление, память, фотографии и татуировки Prisoner обслуживает `jobs/code/job_types/prisoner/spawn.dm`. Преступление выбирается один раз при создании тела, включая Random; модульный `post_equip()` использует тот же выбор, вызывает общее оснащение родительского job-outfit и пропускает preview/повторные эффекты. Адаптер `jobs/code/records.dm` передаёт конкретный первоначальный record модульному обработчику после создания записи. Исходный `code/modules/jobs/job_types/prisoner.dm` сохранён; его ранняя подписка CREWMEMBER_JOINED снимается модульным `New()`. Donor-модуль добавляет подписку, варианты, инструкции и параметры вакансий/спавна.

Расширения назначения находятся в `jobs/code/controller/assignment.dm`: wrapper допуска один раз вызывает штатные account-age/playtime/ban проверки, сохраняет их отказы и проверяет выбранного персонажа после SQL. Затем модуль фиксирует профиль и вызывает штатный `assign_role()` с уже выполненной проверкой. Родитель владеет счётчиком вакансий и назначением роли. `job_slots_preferences` использует зафиксированный профиль при штатном `apply_prefs_job()` без повторного выбора или загрузки слота. Проверки после ожиданий, создание тела и передача игрока сохраняют внутренние точки вызова в ядре, поскольку зависят от конкретной фазы входа.

Дополнения к `check_job_preferences()`, `Destroy()`, `Logout()`, middleware приоритетов и Dynamic candidacy реализованы модульными переопределениями с вызовом родителя. Форматирование профиля и причины отказа для latejoin находятся в `jobs/code/ui/latejoin.dm`: модуль дополняет готовые строки штатного `ui_data()`, сохраняя динамическую видимость и отбрасывая результат при смене профиля во время проверки. Альтернативные входы для admission, случайного выбора и ожидания шаттла находятся в модуле; оборудование, перенос mind и дальнейший учёт продолжают выполнять сохранённые native тела процедур. Новые определения сигналов находятся в `_defines220`; Blood Worm снимает однократный обработчик после проверки тела и при отмене назначения.

[Граница с ядром](CORE_BOUNDARY.md): полный список оставшихся врезок PR, восстановленные файлы, владельцы состояния и причины сохранения фазовых точек входа.

Обработчик latejoin в модуле начинает с `. = ..()` и уважает штатную UI-авторизацию, затем обрабатывает выбранную профессию либо вызывает `handle_native_ui_action()`. В ядре добавлен только заголовок продолжения; исходный switch остаётся единственной реализацией остальных действий. Color action и проверка профиля Blood Worm также вынесены в модули; соответствующие native-файлы полностью восстановлены.

Шаблоны новых должностей доступны через штатную авторизацию CentCom ID-программы. Donor-модуль регистрирует их после родительского `setup_tgui_lists()`; повторный вызов не создаёт дубликатов. Подписка проверяется при выборе профессии и окончательном назначении; полученные предметы и доступы используют обычные игровые правила.

Регрессионные проверки расширений хранятся отдельно от игрового репозитория. Внешний набор подключает их к штатным unit tests только в своей временной копии исходников; обычный `tools/build/build.bat dm-test` запускает штатный набор BandaStation. Внешние проверки охватывают тиры/варианты, экипировку, деньги и переполнение, preview, ID/PDA, профили, окончательный допуск и возврат вакансий, handover, точную запись Prisoner и отмену Dynamic. Полноценная ручная проверка требует BYOND-клиента: обычный Cargo Technician/Доставщик, донатная роль и поздний Prisoner с осмотром экипировки и ID.

Проверка outfits подтверждает выдачу объявленных вещей, а не полноту согласованного комплекта каждой роли. Отдельные donor_seclown_equipment и donor_honk_rifle проверяют обязательную форму/головной убор/верхнюю одежду/HONK-ружьё четырёх комплектов, штатные эффекты клоуна, preview, реальный безвредный выстрел и зарядку. Admission-тест создаёт собственную prison-точку и подтверждает ограничения/возврат вакансии; он не доказывает размещение на настоящих станционных картах.

Клоун СБ наследует штатный outfit клоуна; его skillchip, clumsy, faction и post_equip не копируются. Детектив, смотритель и кадет получают нативные головные уборы и верхнюю одежду. Два HONK-ружья используют штатные стрельбу и зарядку energy gun; снаряд вызывает pop_burst() существующей игрушки snappop, без урона, оглушения или механики banana honker. Импортированные DMI содержат только необходимые состояния формы и ружья; источник и лицензия указаны в [ATTRIBUTION](icons/ATTRIBUTION.md).

Значки профессий используют штатные поля sechud_icon/sechud_icon_state ID trim: они видны на HUD и в Orbit. Preferences показывает вариант активного профиля; latejoin — вариант назначенного профессии профиля через нейтральный get_character_job_icon(). Доступы и каноническая профессия ID не меняются. Варианты художника, подмастерья, дворецкого, горничной и бесплатного Доставщика наследуют свои обычные trims, заменяя только значок. Пиксели оригинального HUD адаптированы к координатам TG; trainee и HONK squad не портируются.

Для маппинга доступны [нативные start/override landmarks](code/landmarks/donor.dm) для каждой из 22 новых профессий. Обычный /obj/effect/landmark/start/donor/<role> задаёт старт раунда; поздний вход остаётся штатным arrivals. Вариант /override имеет jobspawn_override=TRUE и delete_after_roundstart=FALSE: штатный код использует его для обоих входов. Все альтернативные названия используют точку канонической профессии. Cargo/Доставщик используют существующий cargo_technician landmark. Для Prisoner есть существующий start/prisoner и постоянный start/prisoner/latejoin с портированными редакторскими иконками; при donor gate оба проходят прежнюю проверку безопасной свободной клетки в /area/station/security/prison на станционном z. Старый Paradise spawner не добавляется. Определения типов не означают расстановку на игровых картах; выбор клеток остаётся работой маппера.

donor_job_hud_icons проверяет реальные glyphs выбранных вариантов и пригодность для UI, donor_job_landmarks — потребление всех 22 типов нативными roundstart/latejoin процедурами и удаление override из штатного списка. Это отдельные fixture-проверки, а не доказательство размещения на конкретной карте.
